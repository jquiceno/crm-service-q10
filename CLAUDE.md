# crm-service — Project Instructions

## Commit message convention (regla de oro)

Every commit message must follow this exact structure:

```
type: short descriptive message in English
```

- `type` — a conventional commit type such as `feat`, `fix`, `docs`, `chore`, `refactor`, `test`, `perf`, `style`.
- The descriptive message is always in English, short and clear, regardless of what language the conversation happened in.
- **Before running the commit, always show the proposed message and get explicit confirmation that it's clear.** Only commit after that confirmation.
- **Do not run `git push` after committing.** Leave commits local; the user pushes them together, in a batch, when ready.
